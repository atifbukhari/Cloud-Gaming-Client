# Cloud Gaming MVP - Client Fork Handoff

## Authoritative continuation point

Hero concept: **One GPU. Any screen. No console.**

The demo must balance wow factor, market fit, and technical credibility. The strongest hero journey is Android TV / Google TV as the main display, with an Android phone as the eventual controller. The same client should also run directly on Android phones/tablets. The technical reveal is multiple independent sessions sharing one GPU, with client/server telemetry proving quality and density.

## Agreed user journey

One-time pairing remains an onboarding/engineering step. After pairing, the consumer flow is:

**Open branded client -> game cards -> select game -> stream launches automatically.**

Server names, IP addresses, Moonlight terminology, and engineering settings should be hidden from the normal flow. Engineering controls stay accessible secondarily. The later TV journey should show a QR code so a phone can join as controller without requiring Bluetooth setup on the TV.

## Demo games

- **Primary showcase:** SuperTuxKart.
- **Density / multi-session:** Xonotic.
- **Optional higher-wow later:** War Thunder, only after Linux/controller/anti-cheat/licensing validation.
- **Fallback:** Veloren.
- **Engineering-only:** Test Ball; do not expose in final catalogue.

## Implemented in demo-client-v1

The Android application ID is `com.atifbukhari.cloudgaming`. The Java namespace intentionally remains `com.limelight` to minimize risk to the streaming core. Visible naming is **Cloud Gaming / Cloud Gaming (Demo)** and demo version is `12.2-demo1`.

When exactly one paired online host exists, the demo client automatically skips the PC/server picker and opens the game catalogue. The catalogue uses the heading **Cloud Gaming** and tagline **One GPU. Any screen. No console.** Game selection still uses Moonlight's existing direct-launch path; the protocol, decoder, input, and controller core are not being rewritten.

Google Mobile Ads test integration is present using Google's official sample App ID/banner unit. Ads are test-only, catalogue-only, hidden on Android TV/Leanback devices, and never shown over gameplay. No production IDs are present.

Demo telemetry is local-only in v1. The build forces Moonlight's real performance overlay visible during streaming and records session start, connection stages, state changes, failures, termination, and `onPerfUpdate` output. Events are stored as bounded local NDJSON. A hidden **Demo telemetry** screen can view, refresh, and clear them. There is no background uploader.
